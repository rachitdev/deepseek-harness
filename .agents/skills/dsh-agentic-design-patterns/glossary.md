# Glossary — Agentic Design Patterns

**A2A (Agent2Agent Protocol)** — Open HTTP-based standard for communication and collaboration between agents built on different frameworks (Ch 15)
**ACI (Agent-Computer Interface)** — The layer letting an agent perceive and manipulate a GUI: screenshot → element recognition → contextual interpretation → action (Ch 23)
**Agent Card** — An A2A agent's digital identity: JSON with identity, endpoint URL, version, capabilities, skills, I/O modes, and auth requirements (Ch 15)
**AgentSpace** — Google platform for an "agent-driven enterprise": unified search, enterprise knowledge graph, no-code Agent Designer (Ch 25)
**AgentTool** — ADK wrapper letting one agent invoke another as if it were a function (Ch 7)
**Agentic RAG** — RAG plus a reasoning layer that validates sources, reconciles conflicts, decomposes queries, and reaches for external tools (Ch 14)
**AlphaEvolve** — Google agent pairing an LLM ensemble with automated evaluation and evolution to discover and optimize algorithms (Ch 9)
**Anomaly Detection** — Identifying unusual agent actions signalling error, attack, or emergent undesired behavior (Ch 19)
**APE (Automatic Prompt Engineering)** — Using LLMs to generate, evaluate, and refine prompts (Ch 22)
**Artifact** — In A2A, an agent's tangible task output, composed of parts and streamable incrementally (Ch 15)
**Auto-Flow** — ADK behavior where defining `sub_agents` enables LLM-driven delegation automatically (Ch 2)
**BM25** — Keyword-based retrieval ranking chunks by term frequency, without semantic understanding (Ch 14)
**Chain of Debates (CoD)** — Microsoft framework where multiple diverse models argue to improve accuracy and reduce bias (Ch 17)
**Chain-of-Thought (CoT)** — Prompting the model to generate intermediate reasoning steps before the answer (Ch 17, 22)
**Checkpoint and Rollback** — Treating validated agent state as a commit and rollback as fault tolerance (Ch 18)
**Chunking** — Breaking documents into smaller retrievable pieces while preserving context (Ch 14)
**Clipping (PPO)** — The trust region preventing policy updates too far from the current strategy (Ch 9)
**Concept Drift** — Performance degrading as input distribution or the environment shifts (Ch 19)
**Contextual Pruning** — Minimizing prompt token count by summarizing and selectively retaining history (Ch 16)
**Context Engineering** — Designing and delivering the complete informational environment before generation: system prompt, retrieved documents, tool outputs, implicit data (Ch 1, 22)
**Context Staging Area** — A per-task directory of goals, code, and docs assembled by a developer for a coding agent (Ch 28)
**Context Window** — The maximum tokens a model processes at once; short-term memory for LLM agents (Ch 8)
**contextId** — Server-generated A2A identifier grouping related tasks for continuity (Ch 15)
**Contractor (Advanced)** — Agent bound by a formalized contract with verifiable deliverables, negotiation, self-validation, and subcontracting (Ch 19)
**Critique Agent** — A dedicated evaluator providing feedback for self-correction, performance monitoring, and routing refinement (Ch 4, 16)
**Deep Research** — Agentic tools granted a time budget to iteratively search, identify gaps, and synthesize a cited report (Ch 6, 17)
**Delimiters** — Backticks, XML tags, or markers separating instruction, context, examples, and input in a prompt (Ch 22)
**DPO (Direct Preference Optimization)** — Aligning an LLM directly on preference pairs, skipping the reward model (Ch 9)
**Dynamic Re-prioritization** — Modifying task priorities as circumstances change (Ch 20)
**Elo Tournament Ranking** — Pairwise comparison of hypotheses via simulated debate; found concordant with accuracy (Ch 21)
**Embeddings** — Numerical vector representations capturing semantic meaning; similar meanings sit close together (Ch 14)
**Episodic Memory** — Recall of past events and how tasks were accomplished; often few-shot examples (Ch 8)
**Escalation Policy** — Protocol dictating when and how an agent hands off to a human (Ch 13)
**EventActions.state_delta** — ADK mechanism for complex state updates attached to an appended event (Ch 8)
**Evalset File** — ADK artifact holding multiple long sessions for integration testing (Ch 19)
**Exact / In-order / Any-order Match** — Trajectory comparison strictness levels (Ch 19)
**Fallback Mechanism** — Automatically switching to a default or cheaper model when the preferred one is unavailable (Ch 16)
**Few-Shot Prompting** — Providing 3–5 input/output examples to demonstrate a pattern (Ch 22)
**FunctionTool** — ADK wrapper turning a Python function into an agent tool (Ch 2)
**GoD (Graph of Debates)** — Debate as a non-linear graph where argument nodes are linked by supports/refutes edges (Ch 17)
**GraphRAG** — RAG over a knowledge graph, navigating explicit entity relationships to synthesize across fragmented sources (Ch 14)
**Graceful Degradation** — Maintaining partial functionality when full recovery isn't possible (Ch 12, 16)
**Grounding** — Connecting outputs to verifiable real-world sources to ensure accuracy and reduce hallucination
**Guardrails** — Layered safety controls: input validation, behavioral constraints, tool restrictions, output filtering, moderation, human oversight (Ch 18)
**HITL (Human-in-the-Loop)** — Human judgment integrated into the agent's decision path (Ch 13)
**Human-on-the-Loop** — Humans set policy; the AI executes individual cases autonomously within it (Ch 13)
**HNSW** — Hierarchical Navigable Small World; the algorithm vector databases use for fast approximate search (Ch 14)
**In-Context Learning** — Learning a new task from examples in the prompt, without retraining
**Instruction Subversion (Jailbreaking)** — Prompts designed to bypass an LLM's safety features and ethical restrictions (Ch 18)
**JSON-RPC 2.0** — The payload protocol A2A uses over HTTP(S) (Ch 15)
**LCEL (LangChain Expression Language)** — The `prompt | model | parser` pipe syntax for composing chains (Ch 1, 24)
**LangGraph** — Stateful, cyclical graph framework extending LangChain for agentic loops (Ch 24)
**Least Privilege** — Granting an agent the minimum permissions its task requires, limiting blast radius (Ch 18)
**LiteLLM** — Adapter integrating models not natively supported by ADK's default Agent (Ch 16)
**LLM-as-a-Judge** — Using an LLM with a rubric to evaluate another agent's output on subjective qualities (Ch 19)
**LoopAgent** — ADK construct running sub-agents repeatedly until an escalation condition or `max_iterations` (Ch 7)
**Many-Shot Learning** — Including hundreds of examples in-prompt, enabled by long context (Ch 22)
**MASS (Multi-Agent System Search)** — Three-stage automated optimization of multi-agent prompts and topology (Ch 17)
**MCP (Model Context Protocol)** — Open client-server standard for LLMs to discover and use external tools, resources, and prompts (Ch 10)
**MCPToolset** — ADK client handle for an MCP server, via Stdio or HTTP parameters, with an optional tool filter (Ch 10)
**Memory Bank (Vertex)** — Managed service asynchronously extracting, storing, consolidating, and resolving contradictions in user facts (Ch 8)
**MemoryService** — ADK interface to long-term searchable knowledge (`add_session_to_memory`, `search_memory`) (Ch 8)
**Multimodality** — Processing and generating across text, images, audio, and video (Ch 23)
**Network / Supervisor / Hierarchical / Custom** — The multi-agent interrelationship topologies (Ch 7)
**Observation** — The tool result returned to the agent in a ReAct loop (Ch 17)
**OpenRouter** — Unified API endpoint with automated model selection (`openrouter/auto`) and sequential model fallback (Ch 16)
**output_key** — ADK field routing an agent's final text response into session state (Ch 3, 8)
**PALMs (Program-Aided Language Models)** — LLMs generating and executing code to offload precise computation (Ch 17)
**ParallelAgent / SequentialAgent** — ADK orchestrators for concurrent and ordered sub-agent execution (Ch 3)
**Parallelization** — Executing independent components concurrently, then converging on synthesis (Ch 3)
**Persona Pattern** — Describing the *audience* (rather than the model's role) to tailor language and complexity (Ch 22)
**PPO (Proximal Policy Optimization)** — RL algorithm making small clipped policy updates for stable improvement (Ch 9)
**Precision / Recall (trajectory)** — Relevance of predicted actions; coverage of essential actions (Ch 19)
**Procedural Memory** — The agent's rules and core instructions, often self-refined via Reflection (Ch 8)
**Producer–Critic model** — Splitting generation and evaluation into two roles with distinct personas (Ch 4)
**Prompt Chaining** — Decomposing a task into a sequence of focused prompts, each feeding the next (Ch 1)
**Reflection** — Evaluating one's own output against criteria and refining it (Ch 4)
**ReAct (Reason and Act)** — Interleaved Thought → Action → Observation loop (Ch 17, 22)
**Resource-Aware Optimization** — Managing computational, temporal, and financial resources at runtime (Ch 16)
**RLVR (Reinforcement Learning from Verifiable Rewards)** — Training reasoning models on problems with known answers to learn long-form reasoning (Ch 17)
**Routing** — Conditional dispatch to the appropriate tool, chain, or sub-agent (Ch 2)
**RunnableBranch / RunnableParallel / RunnablePassthrough** — LCEL constructs for branching, concurrency, and carrying input through (Ch 2, 3)
**Scaling Inference Law** — Performance improves with compute allocated at inference; a smaller model with a bigger thinking budget can beat a larger one (Ch 17)
**Self-Consistency** — Generating multiple reasoning paths at higher temperature and majority-voting the answer (Ch 17, 22)
**Self-Correction** — Internal evaluation and refinement of generated content (Ch 17)
**Semantic Memory** — Retained facts and preferences; a user profile or a collection of fact documents (Ch 8)
**Semantic Search** — Retrieval by meaning via embedding proximity rather than keyword overlap (Ch 14)
**Session / State** — ADK's chat thread and its temporary key-value scratchpad (Ch 8)
**SICA (Self-Improving Coding Agent)** — Agent that modifies its own source code against an archive of scored past versions (Ch 9)
**SMART Goals** — Specific, Measurable, Achievable, Relevant, Time-bound (Ch 11)
**SSE (Server-Sent Events)** — Persistent one-way server-to-client streaming, one of A2A's interaction mechanisms (Ch 15)
**State Prefixes (`user:`, `app:`, `temp:`)** — ADK conventions declaring scope and persistence of state keys (Ch 8)
**Step-Back Prompting** — Asking for a general principle first, then using it as context for the specific task (Ch 22)
**Structured Output** — Requesting JSON/XML/CSV so results are machine-parseable; limits hallucination (Ch 22)
**System Card** — Published delineation of operational hazards and safeguards for an agent that acts online (Ch 23)
**Task (A2A)** — Asynchronous unit of work with an id and states: submitted, working, completed (Ch 15)
**Terminal-Bench** — Evaluation framework for CLI agents; 80 curated tasks with the minimal Terminus agent as testbed (Ch 26)
**Test-Time Compute Scaling** — Allocating more inference computation to iteratively reason and improve outputs (Ch 21)
**Tool Use / Function Calling** — Describing external functions so the model can emit a structured call the system executes (Ch 5)
**ToT (Tree of Thoughts)** — Branching exploration of multiple reasoning paths with backtracking (Ch 17, 22)
**Trajectory** — The sequence of steps an agent takes; the primary unit of agent evaluation (Ch 19)
**Trusted Tester Program** — Staged access model for gathering real-world feedback on a discovery system (Ch 21)
**Unknown Unknowns** — What exploration targets, as distinct from optimizing known variables (Ch 21)
**Vector Database** — Store optimized for embedding search: Pinecone, Weaviate, Chroma, Milvus, Qdrant, pgvector (Ch 14)
**Vertex AI Extension** — API wrapper executed automatically by Vertex AI, unlike manually-executed function calls (Ch 5)
**Vibe Coding** — Conversational, iterative development focused on the "what" rather than the "how" (Ch 23, 28)
**VSearchAgent** — ADK agent answering from a Vertex AI Search datastore with grounding attributions (Ch 5)
**Well-Known URI** — `/.well-known/agent.json`, the standardized path for A2A Agent Card discovery (Ch 15)
**Zero-Shot / One-Shot Prompting** — Providing no examples, or one, before the task (Ch 22)
