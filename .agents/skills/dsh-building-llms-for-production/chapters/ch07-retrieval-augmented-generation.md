# Chapter VII — Retrieval-Augmented Generation

## Core Idea

RAG (originally from Meta's FAIR team) inserts an **information-retrieval step
before generation**: embed the user's question, find semantically nearest
chunks in a vector store, and paste them into the prompt. This attacks
hallucination at its root — the model answers from supplied evidence rather
than parametric memory — and buys two things fine-tuning cannot: **citable
sources** and **knowledge you can update without retraining**. A working RAG
system is four replaceable stages: *load → split → embed/store → retrieve*,
wrapped in a chain.

## Frameworks Introduced

### The RAG pipeline

| Stage | LangChain class | Decision it forces |
|---|---|---|
| Load | `TextLoader`, `PyPDFLoader`, `SeleniumURLLoader`, `GoogleDriveLoader` | what source formats you support |
| Split | `CharacterTextSplitter`, `RecursiveCharacterTextSplitter`, `TokenTextSplitter`, `NLTKTextSplitter`, `SpacyTextSplitter`, `MarkdownTextSplitter` | chunk size and overlap |
| Embed + store | `OpenAIEmbeddings`, `HuggingFaceEmbeddings`, `CohereEmbeddings` → `DeepLake` (or Chroma etc.) | embedding model and vector store |
| Retrieve | `db.as_retriever()`, `ContextualCompressionRetriever` | top-k, distance metric, compression |
| Generate | `RetrievalQA.from_chain_type(...)` | chain type: stuff / map_reduce / refine |

### Index vs retriever
An **index** is the data structure that organizes stored data for fast search
(in LangChain, predominantly vector-database-backed). A **retriever** is the
thing that queries it: it exposes `get_relevant_documents(query) -> List[Document]`.
Any object satisfying that interface can be dropped into a chain.

### The three document-combining chain types

| `chain_type` | Mechanism | Use when |
|---|---|---|
| `"stuff"` | inserts all retrieved docs into one prompt | documents are short and few; simplest and cheapest |
| `"map_reduce"` | summarizes each doc separately (Map), then combines the summaries (Reduce) | many docs, parallelizable, context-limited |
| `"refine"` | summarizes chunk 1, then iteratively enriches the running summary with each next chunk | you want the most precise, context-aware result and can pay for sequential calls |

### Contextual compression
The problem: equal-sized chunking returns relevant *and* irrelevant text.
Irrelevant text (1) distracts the model and (2) occupies prompt space that
better material could use.

`ContextualCompressionRetriever` wraps a base retriever with a
`DocumentCompressor`. `LLMChainExtractor` is the standard compressor — it runs
an LLMChain over each retrieved document and keeps only the statements relevant
to the query. "Compressing" covers both trimming a document's contents and
dropping documents wholesale.

The strategic payoff: **let the compressor own precision so the base retriever
can optimize for recall** (raise *k* freely).

### Embeddings
Dense vectors that turn human-perceived semantic similarity into measurable
closeness in vector space. Generated by GPT/LLaMA-family layers for text, CNNs
(VGG, Inception) for images, and by applying image techniques to spectrograms
for audio. They power KNN/ANN similarity search — used for de-duplication,
recommendation, anomaly detection, and reverse image search.

Three embedding providers covered:

| Provider | Model | Note |
|---|---|---|
| OpenAI | `text-embedding-ada-002` | the book's default throughout |
| Hugging Face | `sentence-transformers/all-mpnet-base-v2` | open-source, runs on CPU via `model_kwargs={'device':'cpu'}` |
| Cohere | `embed-multilingual-v2.0` | 768-dim, multilingual, uses dot-product; for cross-language search |

### Deep Lake as vector store
A dual-purpose deep-learning database *and* multi-modal vector store: images,
audio, video, text, and metadata in one format, enabling hybrid queries over
embeddings *and* attributes. Supports local, cloud, or Activeloop storage;
version control; dataset queries; distributed workloads; and data streaming
into PyTorch/TensorFlow training loops. The book's argument for cloud-hosted:
in production, thousands-to-millions of documents accessed by applications in
multiple locations need one centralized dataset, not a per-machine store.

## Key Concepts

- **Chunk overlap** — characters shared between consecutive chunks. It exists
  so important information is not severed at a chunk boundary; it preserves
  contextual continuity at the cost of duplicated tokens.
- **Text-segmentation process** — (1) break into small semantically meaningful
  units, usually sentences; (2) aggregate them until a size criterion is met;
  (3) emit the segment and restart with overlap. Customizing it means choosing
  *the splitting technique* and *the size criterion*.
- **`RecursiveCharacterTextSplitter` separator cascade** — tries `"\n\n"`
  first, then `"\n"`, then `" "`, then `""`, descending only when chunks are
  still too big. This is what preserves paragraphs > sentences > words.
  Parameters: `chunk_size` (default 100), `chunk_overlap` (default 20),
  `length_function` (default `len`).
- **`length_function` as a token counter** — swapping `len` for a tiktoken-based
  counter makes `chunk_size` mean tokens, which is what actually matters against
  a model's context limit.
- **Retriever search kwargs** — `retriever.search_kwargs['distance_metric'] = 'cos'`
  selects cosine similarity; `retriever.search_kwargs['k'] = 4` returns the four
  nearest chunks.
- **The larger-context-window question** — bigger windows do not make RAG
  obsolete. Feeding everything costs (1) latency, (2) *accuracy decline* when
  relevant facts are scattered through a long document, and (3) inefficient
  resource use on large datasets.
- **LLMChain invocation methods** — `__call__` returns inputs + response under
  `text`; `.apply(input_list)` returns a list of outputs in input order without
  the inputs; `.generate(input_list)` returns an `LLMResult` with
  `finish_reason`, token usage, and model name; `.predict()` / `.run()` are
  interchangeable and best with multiple named inputs.

## Mental Models

- **Retrieval is prompt construction under a budget.** Every token of retrieved
  context displaces a token of something else. Chunking, top-k, and compression
  are all knobs on the same budget.
- **Recall at retrieval, precision at compression.** Two-stage separation lets
  each stage do what it is good at — vector search is cheap and fuzzy, an LLM
  extractor is expensive and sharp.
- **Chunk size has no default answer.** The book is explicit: clean the data
  first (strip HTML), then experiment with sizes, run real queries, and evaluate.
  Time-consuming, but not skippable.
- **Grounding reduces hallucination; it does not eliminate it.** Given a context
  document about kernel features and asked "Is the Linux distribution free?",
  GPT-3 will still answer "Yes" from parametric memory. Short, vague user
  queries are the failure mode, because semantic search cannot retrieve the
  right document from an underspecified question.

## Anti-patterns

- **Stuffing the whole corpus into a long context window** because the model
  supports it — latency, scattered-fact accuracy loss, and cost.
- **Fixed-size chunking with no evaluation loop.** Equal-part splitting is the
  book's own cautionary example: it returned relevant *and* irrelevant text for
  the same query.
- **`chain_type="stuff"` on long documents.** It is only efficient with short
  documents given context limits.
- **Trusting semantic search alone for terse queries.** "Is it free?" retrieves
  by surface similarity and may pull a document that does not contain the answer.
- **`SeleniumURLLoader` for pages that do not need JS.** It boots a browser
  instance per URL — markedly slower — and does not work in Google Colab without
  extra configuration.
- **`TokenTextSplitter` everywhere.** BPE encode/decode round-trips add compute;
  `CharacterTextSplitter` is the faster choice when token boundaries do not matter.
- **Relying on a single source document.** Three stated costs: limited scope,
  full dependence on that document's quality and accuracy, and residual
  hallucination anyway.

## Code Examples

### Minimal end-to-end RAG

```python
from langchain.document_loaders import TextLoader
from langchain.text_splitter import CharacterTextSplitter
from langchain.embeddings import OpenAIEmbeddings
from langchain.vectorstores import DeepLake
from langchain.chains import RetrievalQA
from langchain.llms import OpenAI

docs_from_file = TextLoader("my_file.txt").load()

text_splitter = CharacterTextSplitter(chunk_size=200, chunk_overlap=20)
docs = text_splitter.split_documents(docs_from_file)

embeddings = OpenAIEmbeddings(model="text-embedding-ada-002")
db = DeepLake(dataset_path=f"hub://{org_id}/langchain_course_indexers_retrievers",
              embedding_function=embeddings)
db.add_documents(docs)

retriever = db.as_retriever()
qa_chain = RetrievalQA.from_chain_type(
    llm=OpenAI(model="gpt-3.5-turbo"),
    chain_type="stuff",
    retriever=retriever,
)
qa_chain.run("How Google plans to challenge OpenAI?")
```

### Contextual compression

```python
from langchain.retrievers import ContextualCompressionRetriever
from langchain.retrievers.document_compressors import LLMChainExtractor

compressor = LLMChainExtractor.from_llm(OpenAI(model="gpt-3.5-turbo", temperature=0))
compression_retriever = ContextualCompressionRetriever(
    base_compressor=compressor,
    base_retriever=retriever,
)
retrieved_docs = compression_retriever.get_relevant_documents(
    "How Google plans to challenge OpenAI?"
)
```

### Manual similarity search with cosine

```python
import numpy as np
from sklearn.metrics.pairwise import cosine_similarity
from langchain.embeddings import OpenAIEmbeddings

embeddings = OpenAIEmbeddings(model="text-embedding-ada-002")
document_embeddings = embeddings.embed_documents(documents)
query_embedding = embeddings.embed_query("A cat is sitting on a mat.")

scores = cosine_similarity([query_embedding], document_embeddings)[0]
most_similar_document = documents[np.argmax(scores)]
```

### Open-source and multilingual embeddings

```python
from langchain.embeddings import HuggingFaceEmbeddings, CohereEmbeddings

hf = HuggingFaceEmbeddings(
    model_name="sentence-transformers/all-mpnet-base-v2",
    model_kwargs={'device': 'cpu'},
)

cohere = CohereEmbeddings(model="embed-multilingual-v2.0",
                          cohere_api_key="your_cohere_api_key")
document_embeddings = cohere.embed_documents(texts)   # 768 dimensions
```

### Conversational chain with memory

```python
from langchain.chains import ConversationChain
from langchain.memory import ConversationBufferMemory

conversation = ConversationChain(llm=llm, memory=ConversationBufferMemory())
conversation.predict(input="List all possible words as substitute for 'artificial'")
conversation.predict(input="And the next 4?")   # resolved against history
```

### Custom chain

```python
from langchain.chains.base import Chain
from typing import Dict, List

class ConcatenateChain(Chain):
    chain_1: LLMChain
    chain_2: LLMChain

    @property
    def input_keys(self) -> List[str]:
        return list(set(self.chain_1.input_keys).union(set(self.chain_2.input_keys)))

    @property
    def output_keys(self) -> List[str]:
        return ['concat_output']

    def _call(self, inputs: Dict[str, str]) -> Dict[str, str]:
        return {'concat_output': self.chain_1.run(inputs) + self.chain_2.run(inputs)}
```

Three methods are all a custom chain needs: `input_keys`, `output_keys`, `_call`.

## Reference Tables

### Text splitter selection

| Splitter | Splits on | Pick it when |
|---|---|---|
| `CharacterTextSplitter` | a single character, fixed size | fast, simple, structure does not matter |
| `RecursiveCharacterTextSplitter` | cascading `["\n\n","\n"," ",""]` | default choice — preserves paragraph/sentence/word structure |
| `TokenTextSplitter` | BPE token boundaries | chunk size must be exact in model tokens |
| `NLTKTextSplitter` | NLTK sentence boundaries | sentence integrity matters; not for text lacking word spaces |
| `SpacyTextSplitter` | spaCy sentence boundaries | alternative to NLTK |
| `MarkdownTextSplitter` | Markdown headers, code blocks, dividers | Markdown docs — keeps structural hierarchy |

### Document loaders

| Loader | Source | Gotcha |
|---|---|---|
| `TextLoader` | plain text | `encoding=` argument for non-UTF-8 |
| `PyPDFLoader` | PDF | one Document per page, with `page` in metadata; needs `pypdf` |
| `SeleniumURLLoader` | JS-rendered URLs | slow (browser per URL); attrs: `continue_on_failure`, `browser`, `executable_path`, `headless` |
| `GoogleDriveLoader` | Drive folder/doc IDs | Google Docs only; needs `credentials.json` + service-account setup |

## Worked Example — Customer-support Q&A chatbot

The chapter's flagship tutorial builds a support bot over scraped technical
articles, and is worth following because it ends by *diagnosing its own
failure*.

1. **Ingest.** Eight Beebom how-to URLs loaded with `SeleniumURLLoader`, split
   at `chunk_size=1000, chunk_overlap=0`.
2. **Embed and store.** `OpenAIEmbeddings("text-embedding-ada-002")` into a
   cloud Deep Lake dataset (`langchain_course_customer_support`). Cloud, not
   local, so many application instances share one dataset.
3. **Prompt.** Role-prompting + KB + question, with an explicit anti-fabrication
   instruction:

```python
template = """You are an exceptional customer support chatbot that gently
answers questions.

You know the following context information.

{chunks_formatted}

Answer to the following question from a customer. Use only information from
the previous context information. Do not invent stuff.

Question: {query}

Answer:"""
```

4. **Retrieve, format, generate** at `temperature=0`:

```python
docs = db.similarity_search(query)
chunks_formatted = "\n\n".join(doc.page_content for doc in docs)
prompt_formatted = prompt.format(chunks_formatted=chunks_formatted, query=query)
answer = OpenAI(model="gpt-3.5-turbo", temperature=0)(prompt_formatted)
```

5. **The failure the book reports.** Ask "Is the Linux distribution free?" while
   the retrieved context is about kernel features, and GPT-3 answers "Yes, the
   Linux distribution is free to download and use" — not present in the context.
   The stated diagnosis: hallucination risk falls when the context *directly*
   contains the answer, but short vague user queries make retrieving the right
   document unreliable, so the semantic-search stage cannot be trusted alone.

That last step is the point of the tutorial. A prompt saying "do not invent
stuff" is not an enforcement mechanism.

### Second worked pipeline — YouTube summarizer

Download with `yt_dlp` → transcribe with **Whisper** (`whisper.load_model("base")`;
tiny/base/small/medium/large trade accuracy for speed; trained on 680,000 hours
of multilingual supervised audio) → split → summarize with
`load_summarize_chain(llm, chain_type=...)`, comparing `map_reduce`, `stuff`
(with a custom bullet-point prompt), and `refine` → store transcripts in Deep
Lake and query them via `RetrievalQA` with `chain_type_kwargs={"prompt": PROMPT}`.

## Key Takeaways

- RAG = retrieval step before generation. It reduces hallucination, enables
  citation, and keeps knowledge updatable without fine-tuning.
- Four swappable stages — load, split, embed/store, retrieve — plus a chain type
  that decides how retrieved documents are combined.
- Chunk size and overlap are empirical. Clean data, sweep sizes, evaluate with
  real queries.
- `RecursiveCharacterTextSplitter` is the sensible default; reach for
  token-based or format-aware splitters for specific constraints.
- Contextual compression lets you tune retrieval for recall and recover
  precision afterwards.
- Cosine similarity over `text-embedding-ada-002` is the workhorse; open-source
  (all-mpnet-base-v2) and multilingual (Cohere embed-multilingual-v2.0)
  alternatives exist and swap in through the same LangChain interface.
- Grounding is a strong mitigation, not a guarantee. Vague queries defeat
  semantic search, and the model will fill the gap from parametric memory.
