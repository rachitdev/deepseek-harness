# Cheat Sheet — The Design Thinking Playbook

Canvases, decision tables, defaults and process templates, dense and scannable.
Chapter references point at the file with the full treatment.

## 1. The two cycles

**Micro cycle (Ch 2)** — Understand → Observe → Define point of view → Ideate → Prototype → Test → Reflect. Not linear; re-enter any phase at any time.

**Macro cycle — seven steps with the book's own timeboxes (Ch 2)**

| # | Step | Purpose | Timebox |
|---|---|---|---|
| 1 | Initial brainstorming | Empty the heads, calibrate understanding | 20 min |
| 2 | Critical functionalities | Identify and rank what the user must have | 1–2 h, 10–20 functions |
| 3 | Benchmarks from other industries | Break attachment to the original concept | 30 + 30 + 30 min, then 2–3 prototypes |
| 4 | Dark horse | Lift the borders, accept maximum risk | 50 min build |
| 5 | Funky prototype | Remove all cost and budget restrictions | 1 h |
| 6 | Vision prototype | The groan zone: fuse everything learned | ~2 h; test with **at least 3** users |
| 7 | Concretize step by step | Convergent elaboration | iterative |

**Step 7 sub-stages** — **A** functional prototype (critical variables only = the MVP) · **B** finished prototype (integrate functionalities; "only reality yields truth") · **C** final prototype (elegance; standard components cut cost and risk) · **D** implementation plan — turn those affected into people who are involved.

**Process variants worth recognizing (Ch 2)** — HPI six steps · d.school (Understand + Observe = "empathy") · IDEO: Understand–Observe–Visualize–Evaluate/Optimize–Implement · Swisscom: Hear–Create–Deliver · ISO 13407 · Scrum sprints of 1–4 weeks.

## 2. Problem framing

**Which problem type am I in? (Ch 3)**

| Type | Shape | Process implication |
|---|---|---|
| Simple / well-defined | Clear problem → one solution | Solve it; the path may vary |
| Ill-defined | Unclear problem → several valid solutions | **The normal case**; design for many-solutions |
| Wicked | Unknown problem → partial solution clarifies the problem | Co-evolution; use "How might we…?" and the why technique; linear analysis fails |

**WHY/HOW ladder** — WHY expands the frame, HOW narrows it. Ideal rung: outside the comfort zone, still buildable. Unsure? Start; iteration one corrects the scope.

**Design brief — six blocks (Ch 3)** — design space and scope · existing approaches · design principles · scenarios · next steps and milestones · potential implementation challenges. Short-profile fields: *Problem · Target customer · Goals · Available resources · Competition · Budget · Schedule · Next steps.*

**Formulating the question — three steps (Ch 3)** — 1) who is the user and what is the central task? 2) apply the WH questions (what does the user want to achieve? how?) 3) formulate the question.

**Widening/narrowing operators (Ch 3)** — minimize · maximize · transform · combine · modify/adapt · rearrange/invert · substitute — each asked twice: of your problem, and of an existing solution.

## 3. Understand and observe

**User profile canvas (Ch 1)** — Name · persona description (age, gender, residence, marital status, hobbies, education, position, social environment, milieu, way of thinking) · Jobs-to-be-done · Use cases · Gains · Pains · Photos · Stories.

**Empathy map (Ch 1)** — hearing · thinking and feeling · seeing · speaking and doing · frustration · desire.

**Hook canvas (Ch 1)** — trigger (external/internal) → action (the simplest rewarded action) → variable reward → investment (which reloads the trigger).

**Jobs-to-be-done sentence** — "When ___, I want to ___, so I can ___."

**Persona development loop — 10 steps (Ch 1)** — find the user → build a hypothesis → confirmations → patterns → create personas → define situations → **validation** → dissemination → scenarios → continuous development.

**Critical-assumption grid (Ch 4)** — plot each assumption on *incidental ↔ decisive* × *knowing ↔ ignorant*; test decisive/ignorant first.

**Needfinding interview — six stages (Ch 4)** — introduction (permission to record; no true or false) → open beginning → concrete recent example → grand tour hunting contradictions → reflection (summarize from your view; ask why) → wrap-up **with the recorder still running**.

**Question-bank purposes (Ch 4)** — trace behaviors · gain clarity · explore actively · ask about sequence · ask for examples · explore exceptions · understand connections · inform outsiders · compare processes · imagine the future.

**6 WH grid (Ch 4)** — What / Who / Why / Where / When, each with three sub-questions; find more than one answer per question, amplify conflicting answers, **evaluate only at the end**.

**Mindfulness practices (Ch 5)** — change perspective · full attention · listen actively · reflect on own behavior · read signals · question your readiness for empathy · ask open questions · explore feelings and needs · express your own · act with empathy.

## 4. Point of view

**Four-step PoV procedure (Ch 6)** — A analyze information → B infer the **10 most important insights** and design principles → C mark themes (dot voting), pick **three** thematic areas → D specify and refine the question.

**PoV sentence templates (Ch 6)**

| Approach | Template |
|---|---|
| How might we | "How might we help [user] to achieve [goal]?" / "How many ways are there to achieve [target] for [user]?" |
| Stanford PoV | "[User] needs to [need] because [surprising insight]." |
| Agile user story | "As a [role] I would like to [action], in order to achieve [benefit]." |

**360° inventory (Ch 6)** — Stakeholders: customers (incl. **noncustomers**) · partners · employees · government institutions · residents · competition. Other points of view: time · money · imaginary world · age · culture · geopolitics · time pressure. Plus the **reverse point of view**.

**9-window tool (Ch 6)** — rows super system / system / subsystem × columns past / today / future.

## 5. Ideate

**Brainstorming rules (Ch 7)** — creative confidence · quantity before quality · no criticism in this phase.

**Four levels of idea depth (Ch 7)** — 1 what is the problem? → 2 the brainstorming question → 3 solution ideas → 4 idea variants. Stuck at level 2 ⇒ make them build a physical model.

**SCAMPER (Ch 7)** — **S**ubstitute · **C**ombine · **A**dapt · **M**odify · **P**ut to other uses · **E**liminate · **R**earrange. Skip any question that does not fit.

**Facilitator tricks (Ch 7)** — halftime idea count across groups · "present your two best and two dumbest solutions" · move the room · brain dump first · no role introductions.

## 6. Structure and select

**Clustering schemes (Ch 8)** — A matches the question · B exciting · C out of scope · D today/tomorrow/future · E B2B/B2C/B2B2C · F incremental vs. radical · G dissemination × implementability · H Churchill matrix (importance × urgency, for **measures**).

**Two-tier selection (Ch 8)** — pass 1: speed of dissemination × speed of adaptation (factor in decision makers and your own influence) → pass 2: implementability × financial feasibility, producing implementation alternatives and functional scope.

**Key questions when selection criteria are unclear (Ch 8)** — What might the vision be? · management's personal preferences? · culture, values, morals? · defined growth areas? · minimum financial contribution? · customer needs and market trends?

**Which map? (Ch 8)**

| Job | Map | Caveat |
|---|---|---|
| Order in a brainstorm | Mind map | Shows no correlations |
| Correlations across several concepts | Concept map | ~3 restructurings to get it good |
| Actors, flows (material, energy, money, information), influences | Systems map | Iterate rough → detail |
| Holistic conception of a messy whole | Giga map | Usually only its creators understand it |
| Share a selected concept | Communication sheet | The artifact for step 4 |

## 7. Prototype

**Three principles (Ch 9)** — LOVE IT / CHANGE IT / LEAVE IT · never fall in love with your prototype · prototyping means iterate, iterate, iterate.

**Decision criteria** — human desirability × economic feasibility × technical implementability, **always beginning with the human being**.

**Prototype catalogue — pick by resolution (Ch 9)**

| Resolution | Types | Suited to |
|---|---|---|
| **Low** (early phase) | Sketch · Pinocchio · role playing · bodystorming · fake door · storytelling | Practically everything; experiences |
| **Low–medium** (first solution approaches) | Mock-up · wire frame · chart · paper · storyboard · photo | Websites, products, experiences |
| **Medium** | Video · service blueprint · business model canvas · relabel · pretend to own · Wizard of Oz | Services, business models, complex scenarios |
| **Medium–high / high** | Physical model (3D print, Lego) · open hardware platform · **MVP** · **MVE** | Products, software, ecosystems and platforms |

**Prototyping workshop — seven steps (Ch 9)** — 1 decide the critical functions to build → 2 choose the variant → 3 build (**provide enough material**) → 4 internal green/red feedback → 5 improve prototype *and* presentation → 6 prepare and run the test **in pairs** → 7 improve or discard; if none works, gather more facts and needs.

**Boxing questions (Ch 9)** — front: name, image, slogan, 2–3 promises · back: features, application, content · other sides: who / which goals / when / where / why. Variants: problem box, solution box, project box, process box.

**Shelfing (Ch 9)** — three shelves — product, service, solution — under the categories the customer would search; reveals portfolio gaps and synergies. Discussion attributes: attractiveness, novelty, strategy contribution, differentiation.

## 8. Test

**Four-step sequence (Ch 10)** — prepare (where? how? what? who?) → conduct in real context → document → infer learnings. Every test should say what to **keep**, what to **change**, what to **discard**.

**Roles (Ch 10)** — moderator (bridges reality and prototype, asks) · actor (plays the service roles) · observer (watches; if there is only one, film it).

**Feedback-capture grid (Ch 10)** — Like · Wishes · Questions · Ideas. Alternative set: "I like…" / "I wish…" / "What if…" / "What is the benefit?" — works for groups of 2 to 100+.

**Experiment grid (Ch 10, 19)** — 1 hypothesis "we believe that…" → 2 test "to verify this we will…" → 3 metrics "and measure…" → 4 criteria "we are on the right track if…" → 5 carry out and document → 6 learnings.

**A/B testing rules (Ch 10)** — simple prototypes only (landing pages, single elements) · both versions in the same predefined window · **one variable at a time** · predefined evaluation criteria · show version B only to **new visitors** · valid outcomes include *no statistically relevant preference*.

**Web feedback tool selection (Ch 10)** — A uploads single/variant/sequence prototypes? · B scenario description? · C predefined *and* open questions? · D can you choose the feedback community beyond your own organization?

## 9. Space, team, craft

**Creative space defaults (Ch 11)** — ~**5 m² / 55 sq ft per participant** · natural light · empty the room first · **one or two chairs more than participants**, stackable · organic, free-standing, movable tables · chairs distributed, not arranged · material on spare chairs, not tables · walls kept clear · stack tables **tabletop to the front** · flip chart used on the **squared side** · orange = creativity/flexibility/agility, blue = communication/inspiration/clarity · never run out of working whiteboard markers.

**Sizing** — a project team of **4–12** working for weeks or months, or **8–25** participants for one to two days; feedback providers get stools or textile cubes.

**Work environment = place · people · process · meaningfulness (Ch 11).**

**Team profiles (Ch 12)**

| Profile | Meaning |
|---|---|
| **I** | Depth only; easiest to hire, weakest interdisciplinary contribution |
| **T** | Depth + breadth (empathy, ability to collaborate / interface expertise) |
| **Pi** | Two legs of depth — own specialization plus a second role or leadership |
| **U-shaped team** | Returns to equilibrium after disruption; mistakes do not cost jobs — "safety and security mean productivity" |

**Six rules for an interdisciplinary team (Ch 12)** — common vision (ideally the "How might we" question) · each process step led by its expert · common values, visible at all times · atmosphere of trust · comprehensible feedback · shared processes and quality standards.

**Visualization elements (Ch 13)** — text · graphic elements (containers, folders, lines, arrows — write first, enclose after) · icons and symbols (the simpler the better) · figures and emotions (stick, round, star) · colour (few, to highlight). Four properties: focus on what's important · be specific · be comprehensible · kindle interest. Flip chart letters **at least 3–3.5 cm / 1.5 in**, pen set down squarely, written with the wide side.

**Chart selection (Ch 13)** — numbers → bar or pie · structures and processes → organizational charts · relative sizes and positioning → portfolio charts.

**Story elements (Ch 14)** — emotionally significant initial situation · likable main character · conflicts and hindrances · recognizable change (before/after) · climax with the moral.

**Golden Circle (Ch 14)** — WHY (purpose, limbic, trust and decisions) → HOW (USP, key values, workflow) → WHAT (products, results). Digital storytelling: keep it short · linear narrative · show, don't tell.

## 10. Facilitation

**Workshop planning — four steps (Ch 15)** — 1 determine the context (why? what result?) → 2 plan (process, participants, environment, information) → 3 implement according to demand (are we in flow? adapt?) → 4 reflect and learn.

**ARE IN (Ch 15)** — Authority · Resources · Expertise · Information (including informal) · Need.

**Method selection (Ch 15)**

| Situation | Method |
|---|---|
| Large change project, difficult dialog, decisive turning points to document | Visual facilitating / graphic recording |
| A system that "already works" and is never questioned | Appreciative inquiry |
| Any group work, especially organizational development | The circle way |
| Final presentations of design thinking projects | Open space technology |
| Sharing knowledge across groups, fast intense small-circle discussion | World café |
| Impulse-driven exploration with mental leaps | Dynamic facilitation (four lists: questions · ideas · concerns · information) |

**Causes of death of a decision (Ch 15)** — indefinite postponement · a decision made that was never discussed · the boss deciding before the divergent ideas are thought through · killer phrases.

**Success test** — "If everything remains the same afterward, the facilitation has failed in its purpose."

## 11. Organization, foresight, systems, business model

**Three organizational phases (Ch 16)** — pioneer (» family) → diversification (» machine, silos, efficiency) → integration (» organism). Effective design thinking unfolds only in an integrated organization.

**Enshrining design thinking — three elements (Ch 16)** — company management (customer centricity as a strategic theme, clear vision, basis of trust) · structure and culture (open, collaborative, networked, autonomous) · holistic implementation of the customer experience (shared with ecosystem partners).

**CCScore loop (Ch 16)** — 1 measure by online assessment across a **representative cross-section** → 2 method-based reflection (the U procedure) turning drivers into written strategies, **with** employees → 3 action plan, monitored, re-measured. Low score = "customers are tolerated"; high = "customers are in the focus."

**Foresight Framework — five stages (Ch 17)** — Perspective (understand the past) · Opportunity (extrapolate changed needs) · Solution · Team · Vision. Three tools per stage. WYFIWYG: what you foresee is what you get.

**Trend maturity (Ch 17)** — weak signal → micro trend → macro trend → mega trend. Combine bands of the progression curve (basic technologies · accelerators · future scenarios) to construct new ideas.

**Pictures of the Future — three steps (Ch 14)** — extrapolate from today (note importance, impact, maturity) → strategic visioning outside-in (four scenarios work well) → retropolate: what to research, build, hire and redesign now.

**Systems thinking problem-solving cycle (Ch 18)** — 1 initial problem → 2 mapping of reality → 3 situation analysis (rough to detail; models, experiments, data analytics, SWOT) → 4 goal formulation = decision criteria → 5 search for solutions **in variants** → 6 evaluation (evaluation matrix, simulations) → 7 decision, else iterate. Steps 1–4 problem space, 5–7 solution space.

**Three key questions for understanding a system (Ch 18)** — relationships (→ list of insights) · perspectives (→ list of variants) · framework conditions (→ delimit and describe the systems). Inside the boundary: strengths and weaknesses. Outside: opportunities and risks.

**Which mindset leads (Ch 18)** — ideas / conception / feasibility, simple functionalities, user interaction ⇒ **design thinking**. Requirements engineering, detailed design and simulation, production, integration and validation, launch ⇒ **systems thinking**.

**Lean canvas build order (Ch 19)** — 1 problem → 2 customer segments → 3 unique value proposition → 4 solution (MVP/MVE) → 5 existing alternatives → 6 channels → 7 unfair advantage → 8 key metrics → 9 revenue streams → 10 cost structure → 11 short concept (X-for-Y) → 12 experiment reports. *Typical start at 1 or 4.* Then the viability check: satisfied? NO → back to 1–11; YES → continue.

**Six digital entry points (Ch 19)** — A the problem · B digitize a physical object · C a missing digital alternative · D an unfair advantage built as an ecosystem · E digital channels · F an existing model absent from your market.

**Business model archetypes (Ch 19)** — circular value creation (closed loop) · servitization (renting and leasing, pay-per-use) · frugality (co-creation, on-demand).

**NABC (Ch 19)** — Need (which customers, main need, problems, opportunity) · Approach (solution, product/service proposal, go-to-market, how we earn money) · Benefits (qualitative and quantitative, told as a story) · Competition (alternatives today and future, risk, how it was solved before).

**Ten value-proposition checks (Ch 19)** — embedded in a business model · matters to most customers · they will spend a lot on it · the problem is unresolved · **few tasks solved extremely well** · covers emotional and social components · aligned to the customer's own measure of success · differentiated · better in at least one dimension · hard to copy.

**Service blueprint build order and colours (Ch 19)** — 1 customer actions on the timeline → 2 **green** touchpoints → 3 **blue** visible provider activities → 4 invisible activities → 5 **orange** supporting systems → 6 **red** critical points, errors, risks. The customer interaction line separates customer from provider activities.

**Problem to Growth & Scale — six steps (Ch 19)** — design thinking → research → co-creation → lean start-up (test & validate) → business ecosystem design and agile development (launch & execute) → scale (growth).

## 12. Numbers and defaults

| Setting | Default |
|---|---|
| Users per qualitative test | **No more than 5**, many rounds |
| Users for the vision prototype | **At least 3** |
| Pilot before a test series | **1 person**, with time to fix errors |
| Critical functions to draft and rank | **10–20** |
| Insights condensed at the PoV step | **10**, narrowed to **3** thematic areas |
| Space per workshop participant | **~5 m² / 55 sq ft** |
| Chairs | Participants **+1 or 2**, stackable |
| Team for a multi-week project | **4–12** |
| Workshop group for a 1–2 day topic | **8–25** |
| Company shape Lilly aims at | **15–25 employees**, each technical skill represented multiple times |
| Flip-chart letter height | **3–3.5 cm / 1.5 in** or bigger |
| Distant scenarios in strategic visioning | **4** |
| Scrum sprint | **1–4 weeks** |
| Resource rule for any test or experiment | Could it be done in **half the time with half the resources**? |

## 13. Tells and smells — symptom → diagnosis → fix

| Symptom | Diagnosis | Fix |
|---|---|---|
| One group's idea count is far below the others | They started discussing and evaluating during divergence | Halftime count; restate no-criticism; separate evaluation into its own step (Ch 7) |
| The wall says "ergonomic," "safely," "cheaper" | Requirements have been collected instead of ideas | Name the category, re-ask the question, make them build a physical model (Ch 7) |
| The team cannot let go of the original concept | Too little creative risk taken | Benchmarks from other industries, then dark horse, then funky prototype (Ch 2) |
| Divergence never ends | No ranked critical functionalities to converge against | Fix criticals early; match ideas against them; outsource the vote (Ch 2) |
| The same rejected ideas resurface every phase | Divergent ideas were never actually discussed | Facilitate the groan zone explicitly rather than shortcutting it (Ch 15) |
| The room feels dysfunctional mid-ideation | Normal emergence, not a broken group | Name it; hold the group; keep exchange going instead of monologues (Ch 15) |
| "That will never work" from management | Killer phrase: decision maker cannot or will not penetrate the solution, or fears the depth of change | Build a prototype first (submarine), tell the story, secure ARE IN Authority (Ch 8, 14, 15) |
| Blank stare when asked what fails in the user's day | Ideas were not based on real needs | Do needfinding; do not send them out until they know what to look for (Ch 4) |
| Everyone likes the prototype | Tested with friends, colleagues or its builders | Test with neutral people who did not build it (Ch 4, 10) |
| Test feedback is vague | Only one solution was shown | Present two or three described variants so users can compare (Ch 10) |
| You keep explaining how it works | The user's own interpretation has been overwritten | Say nothing; observe misuse; answer questions with questions (Ch 10) |
| The persona could be two completely different people | Thin persona | Dig one level deeper and validate against a real person (Ch 1) |
| The solution excites only lead users | White elephant risk: high cost, low implementability, hard to stop | Check the needs of early majority customers too (Ch 4) |
| The team's output is a compromise between specialties | Multidisciplinary, not interdisciplinary | Common vision, common values, shared ownership of the whole (Ch 12) |
| The team fractures at the first friction | Not a U-shaped team | Build psychological safety before performance expectations (Ch 12) |
| A stylish creative room stands empty | Designed *for* the team rather than *with* it | Co-design it and iterate it as a prototype (Ch 11) |
| Creative flow stalls mid-session | Material ran out — often dried-out markers | Caddy checklist; check every pen before the session (Ch 11) |
| Great design thinking results never get implemented | The organization lacks the fitness, not the method | Company-wide network, decision-maker buy-in, close the CCScore loop (Ch 16) |
| The only shared company goals are profit and EBIT | Meaning got lost in the diversification phase | Customer centricity as a strategic theme with a clear vision (Ch 16) |
| Customer centricity was measured and nothing changed | Measurement mistaken for intervention | Develop measures *with* employees, plan, monitor, re-measure (Ch 16) |
| Nobody understands the map on the wall | A giga map was produced for an audience | Use a communication sheet for sharing; keep the giga map for the makers (Ch 8) |
| Foresight output is extrapolated past data | This is futurology, not strategic foresight | Design distant scenarios outside-in, then retropolate (Ch 14, 17) |
| Scenarios were produced, then routine resumed | The transformation was never prepared for | Expose many decision makers; publish scenarios at regular intervals (Ch 14) |
| The model is a clean cause/effect chain | Linear model applied to a complex system | Redraw with feedback loops and stabilize them against a desired level (Ch 18) |
| Forecasts hold technically but fail in practice | Social systems and human motives entered the model | Expect forecast quality to drop; monitor, do not assume (Ch 18) |
| The business model was finished in an afternoon | Too fast; it is a plan, not a hypothesis set | Build variants, run experiment reports, re-check viability (Ch 19) |
| The value proposition addresses many tasks | Fails check 5 of ten | Aim at few tasks, pains and gains and solve them extremely well (Ch 19) |
| A service fails in ways nobody predicted | Only the visible layer was designed | Build the service blueprint down to invisible and supporting activities (Ch 19) |
