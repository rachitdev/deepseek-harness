# Agent Note：在单个 decision 请求中完成动态浏览器动作策略

Status: implemented

[English](2026-09-21-dynamic-browser-action-policy.md) | 中文

## Problem

`decideEgoStep` 只问一个固定的 `element` 选择题，因此永远只能返回点击。需要输入文本或选择原生下拉项的页面，通过它根本无法触及，所以该消费方无法驱动一个普通的搜索表单。它同时没有任何调用方，而本仓库也不包含任何浏览器包：这里真正使用的浏览器是外部的 `ego-browser` CLI，通过 Bash 工具驱动。

此前的扫描把 `jev-ultrafast` 的投机式 fan-out 记为"已实现"便就此打住，这是把其中一个机制误当成了该项目的成果。它实测的收益大部分来自别处——浏览器协议调用中位数从 1,092 降到 101，任务时间中位数从 9.450 秒降到 7.092 秒，主要由原子 DOM 快照与有界等待带来，而非 fan-out。本仓库真正缺失的是**动态动作空间**：每次观测都重建元素表，且每个操作各自携带一组有效目标。

## Decision

`decideBrowserAction` 在单个请求中提出一个操作问题，外加页面当前提供的每个操作各一个目标问题。只有与所选操作同名的那个头会被读取；其余的头无法执行任何动作。针对本账户的实测表明，问题数量几乎免费而请求数量并非如此，因此未被使用的头正是这笔交易中便宜的一半。

只有当某个被观测到的控件支持某操作时，该操作才会进入提供方的选项。没有可编辑字段的页面永远不会提供 `TYPE_TEXT`，因此提供方绝不会被要求在无法执行的动作之间做选择。当恰好只有一个控件支持所选操作时，不会提出目标问题：单选项的 choice 不构成决策且会被 seam 拒绝，而选定操作本身就已经确定了目标。

当 `confidence` 低于 `targetConfidenceThreshold`（0.70）时返回 `executable: false` 而不是抛错，因此调用方会重新观测，而不是基于一个弱选择去行动。

该消费方不拥有浏览器。它接收一份已经观测好的元素表，返回一个操作与目标 id。观测、把目标解析回活动节点、新鲜度与遮挡检查，以及 TYPE_TEXT 的取值生成，都仍由调用方负责。

## Measured results

真实提供方，`tests/browser-action-policy.e2e.ts`，四个带标注的步骤：操作与目标 4/4 正确，每步 361–1224 毫秒。其中两个是 `decideEgoStep` 无法表达的步骤——向一个已部分填写的表单中空白的目的地字段输入文本，以及一个仅支持 `SELECT` 的控件。`DONE` 用例返回 0.72，高于阈值但明显低于三个动作用例的 1.00，这正是预期的形态：完成与否是对可见证据的判断，而不是一次目标查找。

上游 Python 实现也在本机针对真实网页做了端到端运行：仅点击的导航 3/3 通过，中位耗时 3.385 秒；一个完整的 TYPE_TEXT 任务耗时 6.973 秒，文本助手由本地 OmniRoute 网关提供。

## Alternatives considered

- **扩展 `decideEgoStep`**——否决。它的返回类型是带元素 id 的单一点击动作；把它加宽为操作联合类型，会在没有任何现有调用方的情况下改变每个既有字段的含义，而它所记录的仅点击步进本身仍然成立。
- **连浏览器运行时一并移植**——本次变更否决。快照、等待与遮挡逻辑是 `jev-ultrafast` 速度的主要来源，但它们属于本仓库并不存在的浏览器包，而此处的浏览器控制已由 `ego-browser` 负责。decision 策略才是契合现有 seam 的那一部分。
- **顺序地分别询问操作与目标**——依据实测否决：两个请求的开销大约是一个的两倍，而单请求形式实测降低 48.6% 延迟且 5/5 决策一致。
- **让该策略同时提供 TYPE_TEXT 的取值**——否决。按构造，decision 答案不携带任何文本，且上游实现刻意选择失败而非臆造字段值。文本生成仍归调用方的文本模型。

## Consequences

- 调用方现在可以通过 decision seam 驱动表单，而不仅仅是链接。
- `decideEgoStep` 仍用于单元素点击步进；两者都被导出，互不取代。
- 只提供一个操作且只有一个控件的页面，现在不再产生目标问题，因此调用方必须读取 `targetId`，而不能假定一定提出过目标头。
- 与 `selectSkill` 和 `assessInstructionDrift` 一样，该消费方目前是一个没有归属方接入 loop 的库函数。
